 DEPLOYMENT
6.1 Deployment Overview:-
After development and testing, FurniFlex was deployed to the cloud so that it can be accessed by
anyone on the internet through a proper domain name over a secure HTTPS connection. The
application is hosted on an Amazon Web Services (AWS) EC2 virtual server running Ubuntu
Linux. The following technologies are used in the deployment:
  AWS EC2 Instance: A virtual server in the AWS cloud on which the complete application
runs. A Security Group acts as a firewall and only allows SSH (22), HTTP (80) and HTTPS
(443) traffic.
 Docker & Docker Compose: The FastAPI backend and the PostgreSQL database run as two
containers managed by Docker Compose, exactly as in development. Data is kept in a Docker
volume so it survives restarts.
 Nginx (Reverse Proxy): Nginx is the single entry point for all traffic. It serves the built React
files directly and forwards (reverse proxies) every /api and /static request to the backend
container on 127.0.0.1:8000. It also terminates SSL, so the backend itself never handles
certificates.
 DuckDNS (Free Domain): DuckDNS is a free dynamic DNS service. It provides the
sub-domain furniflex.duckdns.org and points it to the public IP address of the EC2 instance.
A small cron job keeps the IP up to date.
 Certbot (SSL Certificate): Certbot is the official client for Let’s Encrypt, a free certificate
authority. It proves ownership of the domain, obtains a trusted SSL certificate, configures
Nginx for HTTPS and renews the certificate automatically before it expires (every 90 days).

The figure below shows how the different parts of the deployment are connected. A user’s browser
first resolves the DuckDNS domain to the EC2 public IP, then connects to Nginx over HTTPS.
